## Learned memory

Cascade, the legacy local agent, has persistent cross-session memory in two forms: auto-generated Memories that it stores locally in ~/.codeium/windsurf/memories/ (workspace-scoped — memories made in one workspace are unavailable in another — never committed to the repository, and never shared with teammates), and user-defined Rules (global_rules.md etc.) which are the durable, shareable channel. Users can also prompt "create a memory of ..." at any time. Devin Local — the default local agent in Devin Desktop and the successor harness — does not persist memories between sessions at all; Cognition's migration path is the "Devin: Open Cascade Migration Wizard" command, which moves memories into skills. On the cloud surface, Devin sessions recall cross-session Knowledge items held in the Devin cloud (managed at app.devin.ai/settings/knowledge with repo, organization, or enterprise scoping); Knowledge is deprecated and is being migrated automatically to Skills in Plugins.

## Compatibility notes

Identity: Windsurf is mid-rebrand to Devin Desktop (Cognition). docs.windsurf.com now 308-redirects to docs.devin.ai — the getting-started page cited for this atlas (docs.windsurf.com/windsurf/getting-started) resolves to https://docs.devin.ai/desktop/getting-started. Every evidence link above is the resolved docs.devin.ai URL as fetched, and every path documented here is still read for backward compatibility (the .windsurf/ trees work side by side with .devin/). Three surfaces matter for convention files: Cascade (legacy local agent, full rules/memories/workflows support), Devin Local (default local agent for new tabs; runs the Devin CLI harness, so it reads AGENTS.md through the CLI rules system, uses the same skills discovery, supports subagents and agent plugins, but has no memories or workflows — only paths documented for the shared CLI harness apply to it), and Devin cloud sessions (delegated from the editor; read repository AGENTS.md with a 16 KiB automatic injection limit and .agents/skills, and can run plugin skills, but plugin subagents are explicitly local-only and cloud reading of repository .devin/rules or .windsurf/rules directories is not documented — say "not documented" rather than assuming). Precedence, as far as the docs state it: .devin/ is preferred over legacy .windsurf/ everywhere (for rule directories the Windsurf tree is a fallback, while for the single global_rules.md file only the .devin/ copy is loaded when both exist); root AGENTS.md is always-on while subdirectory AGENTS.md files are glob-scoped; enterprise system rules merge with, and do not override, user-defined rules. Cross-tool config import is a feature of the shared Devin CLI harness: it imports rules, skills, commands, and MCP servers from Cursor, Windsurf, Claude Code (CLAUDE.md, ~/.claude/CLAUDE.md, .claude/skills, .claude/commands, .claude/settings*), GitHub Copilot skills, OpenCode, and Zed — each disableable via read_config_from in ~/.config/devin/config.json or .devin/config.json (all default true); Copilot custom-instruction files and Windsurf workflows are explicitly not imported. Devin Desktop's "Claude Code config reading" setting (which enables .claude/skills scanning) is referenced on the skills page but its UI location is not documented on the pages read. Plugins: Devin agent plugins manifest as .devin-plugin/plugin.json, falling back to .claude-plugin/plugin.json (Claude plugin compatibility) then a root plugin.json; they install at the user level and can carry AGENTS.md, rules/, skills/, agents/, hooks.json, and .mcp.json. They are unrelated to the Windsurf IDE plugins (JetBrains/VS Code — now in maintenance mode), which extend the IDE rather than the agent. Paths that exist but carry no instructions and are therefore not listed as convention files: Cascade MCP config (~/.config/devin/mcp_config.json), Cascade hooks JSON (user: ~/.codeium/windsurf/hooks.json, JetBrains plugin: ~/.codeium/hooks.json, workspace: .devin/hooks.json with legacy .windsurf/hooks.json fallback, system: /etc/devin/hooks.json etc., merged system → user → workspace), and the Devin Local agent config files (.devin/config.json, .devin/config.local.json, ~/.config/devin/config.json). Not documented anywhere in these docs: any Codex-specific convention paths (Codex appears only in agent-handoff pages, not config import) and cloud-session handling of .devin/rules or .windsurf/rules.
