## Compatibility notes

Compatibility posture: OpenCode treats Claude Code as a first-class fallback at both tiers — project CLAUDE.md and global ~/.claude/CLAUDE.md for instructions, .claude/skills (project + global) for skills — each disabled individually via OPENCODE_DISABLE_CLAUDE_CODE_PROMPT / _SKILLS (or wholesale via OPENCODE_DISABLE_CLAUDE_CODE). It also reads .agents/skills (agent-compatible convention) and a deprecated CONTEXT.md. Nothing from Gemini/Cursor/Crush/Kilo is auto-loaded; Cursor/Copilot files enter only if a user lists them in opencode.json's instructions (docs example: ".cursor/rules/*.md") or remote https URLs (5s timeout). Config knobs mirror this: .opencode and ~/.config/opencode use plural subdirs (agents/, commands/, skills/, tools/, themes/) with singular names kept for backwards compatibility. Skill name collisions are not documented to resolve by precedence — docs demand globally unique names, while source effectively lets later scans overwrite earlier ones (config/.opencode dirs load after .claude/.agents, so native dirs win ties); a built-in "customize-opencode" skill is registered first and can be overridden by any disk skill. Instruction discovery is also lazy: reading a file in a subdirectory attaches that directory's nearby AGENTS.md/CLAUDE.md/CONTEXT.md up to the project root, once per message (Instruction.resolve in source).
