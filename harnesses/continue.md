## Learned memory

None - Continue's final release has no built-in learned/auto memory: no memory or memories directory or code path exists anywhere in the repo tree, and its docs nav contains zero mentions of memory; it only persists chat sessions under ~/.continue/sessions and UI state in ~/.continue/.utils/globalContext.json.

## Compatibility notes

Compatibility reads: workspace AGENTS.md (open standard), CLAUDE.md (Claude Code), CLI-only CODEX.md, and workspace .claude/skills in Anthropic SKILL.md format. No support found for GEMINI.md, .cursorrules, .windsurfrules, opencode.json or kilo.jsonc (repo tree grep). Global scope is only ~/.continue - ~/.claude/CLAUDE.md and ~/.claude/skills are NOT read (global skill dir is ~/.continue/skills; core's helper is misleadingly named getClaudeSkillsDir but its global half resolves to ~/.continue/skills). Core assembly order (doLoadConfig.loadRules unshift chain) = colocated rules.md -> .continue/rules+.continue/prompts+agent file -> .continuerules -> config.yaml/hub rules; docs describe rules as newline-joined in toolbar order, i.e. additive, nothing is suppressed, and a duplicate-rule-name warning is emitted if names collide. Notable: AGENTS.md/CLAUDE.md and the whole skills system (ReadSkill tool in core, Skills tool in CLI) are undocumented in the final in-repo docs (only .continue/rules and config.yaml rules appear; docs nav has 0 mentions of skill/memory/agents.md/claude). Core agent-file fallback loop breaks after first probed candidate, so AGENT.md/CLAUDE.md are effectively dead fallbacks in VS Code unless the existence check throws. .continue/agents/*.md is a separate convention for Continue Agents run in CI via `cn -p --agent <file>` (workflow default path .continue/agents), not auto-loaded into the agent's context. Skill entries require a directory containing SKILL.md with name+description frontmatter; sibling files ship with the skill. Legacy JSON path still merges workspace .continuerc.json over ~/.continue/config.json when config.yaml is absent.
