## Skill directories discovered

- `~/.claude/skills/<skill-name>/SKILL.md (Personal — all your projects on this machine; not Cowork/cloud sessions)` — [src](https://code.claude.com/docs/en/skills)
- `.claude/skills/<skill-name>/SKILL.md (Project — sessions in this repository; also searched in every parent directory up to the repository root, and /cd adds the new directory's skills)` — [src](https://code.claude.com/docs/en/skills)
- `<subdir>/.claude/skills/<skill-name>/SKILL.md (Nested — loads lazily the first time Claude reads/edits a file in that subdirectory, or when added via /add-dir; invoked as /apps/web:deploy style directory-qualified name)` — [src](https://code.claude.com/docs/en/skills)
- `.claude/skills/<skill-name>/SKILL.md in a directory passed with --add-dir or /add-dir (Additional directory — that session only; the directory's .claude/commands/ and .claude/agents/ also load, permissions.additionalDirectories does not)` — [src](https://code.claude.com/docs/en/skills)
- `.claude/skills/<skill-name>/SKILL.md in the managed settings directory (Enterprise — all users where the organization deploys it; same system directories as managed-settings.json, e.g. /etc/claude-code/ on Linux)` — [src](https://code.claude.com/docs/en/skills)
- `<plugin>/skills/<skill-name>/SKILL.md (Plugin — loads wherever the plugin is enabled, namespaced as /plugin-name:skill-name; a skill folder with .claude-plugin/plugin.json loads as a plugin named <name>@skills-dir from ~/.claude/skills/ or the project's .claude/skills/)` — [src](https://code.claude.com/docs/en/skills)
- `~/.claude/plugins/ (plugin install root: cloned marketplaces, installed plugin versions, installed_plugins.json install records, per-plugin data; claude.ai-synced plugins download into ~/.claude/plugins/synced/. Plugins load from here at session start)` — [src](https://code.claude.com/docs/en/plugins/loading)
- `~/.claude/skills/synced/ (skills synced from a claude.ai account in terminal sessions; reserved folder name — authored skills at that name are skipped)` — [src](https://code.claude.com/docs/en/skills)
- `.claude/commands/*.md and ~/.claude/commands/*.md (legacy command files, now the same mechanism as skills; a skill wins over a same-named command file; also loaded from nested and --add-dir directories)` — [src](https://code.claude.com/docs/en/skills)

## Learned memory

Built-in learned memory: yes — "auto memory", on by default in local sessions, where Claude writes its own notes (types user/feedback/project/reference) per repository into ~/.claude/projects/<project>/memory/ (entrypoint MEMORY.md, first 200 lines or 25KB loaded into every session; shared across worktrees; relocated via autoMemoryDirectory, toggled via autoMemoryEnabled in ~/.claude/settings.json or CLAUDE_CODE_DISABLE_AUTO_MEMORY=1), and subagents can keep their own persistent memory in agent-memory/<name>/MEMORY.md.

[src](https://code.claude.com/docs/en/memory)

## Compatibility notes

Compatibility: Claude Code now reads AGENTS.md natively (v2.1.277+), by default only when no CLAUDE.md/CLAUDE.local.md exists in the working directory or above; /config "Project instructions" (or pluginConfigs "agents-md@builtin" in user/managed settings) can set claude-md-and-agents-md to read both, claude-md, or managed-only. It does NOT read AGENTS.local.md, AGENTS.override.md, .agents/, GEMINI.md, CRUSH.md, .cursorrules, opencode.json, or kilo.jsonc as instructions. Interop paths: put @AGENTS.md (or @GEMINI.md etc.) in a CLAUDE.md, or symlink (Edit/Write refuse to write through a symlink); /init reads other tools' files (Cursor .cursor/rules/ + .cursorrules, Copilot .github/copilot-instructions.md, and with CLAUDE_CODE_NEW_INIT=1 also AGENTS.md, .devin/rules/, .windsurf/rules/ or .windsurfrules, .clinerules), and /import (v2.1.213+) copies another agent's config including MCP servers, commands, subagents and skills. Skills follow the open Agent Skills standard (agentskills.io, cross-tool SKILL.md) and custom commands were merged into skills (.claude/commands/ still works). Precedence: memory files are all concatenated (broadest to most specific: managed -> user -> project -> local; within a tree, root down to cwd with the cwd-closest read last); skill name collisions resolve enterprise > personal > project, skill beats a same-named command file, plugin skills are namespaced so they coexist, and nested skills coexist with root skills. Loading can be restricted by strictPluginOnlyCustomization, --safe-mode, or bare mode; Cowork and cloud sessions don't read the machine's ~/.claude/skills/ (they use claude.ai account skills); CLAUDE.md from --add-dir directories loads only when CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1, and AGENTS.md from added directories never loads that way. Settings files (settings.json, managed-settings.json, .mcp.json) are configuration, not instruction/context files, and are covered by separate precedence (managed > CLI flags > user/local/project).
